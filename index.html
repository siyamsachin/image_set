Overview

What is image-set()?

A CSS functional notation that provides a set of image options. The browser chooses the most appropriate one based on the device's pixel density and which image formats it supports.

◎Resolution aware

Serve sharp 2x / 3x assets to Retina & high-DPI screens, and lighter 1x files everywhere else.

❖Format aware

Offer modern formats like AVIF or WebP with type(), falling back to JPEG / PNG.

✦Works anywhere

Usable wherever an <image> is accepted — background-image, content, mask-image…

Why it matters

One image doesn't fit every screen

✕Without image-set()

  • Low-res image looks blurry on Retina displays
  • High-res image wastes bandwidth on standard screens
  • No way to prefer AVIF / WebP in plain CSS backgrounds
  • Media-query hacks with min-resolution get verbose

✓With image-set()

  • Browser picks the sharpest suitable image
  • Smaller downloads on low-density devices
  • Modern formats with automatic fallback
  • One declaration — clean & declarative
Syntax

Anatomy of image-set()

image-set( <image-set-option># )
<image-set-option> = [ <image> | <string> ]  [ <resolution> || type(<string>) ]?
background-image: image-set(
  url("logo.avif")   1x type("image/avif"),
  url("logo@2x.png") 2x type("image/png"),
  url("logo.png")    1x type("image/png")
);

img<image> | <string>

A url(), a plain URL string, or even a gradient. Any image except a nested image-set.

2x<resolution>

Optional density descriptor — x, dppx, dpi, dpcm. Defaults to 1x.

()type()

Optional MIME type. Unsupported types are skipped, enabling format fallback.

Example 01 · Resolution switching

Sharp on every display

.hero {
  /* fallback for old browsers */
  background-image: url("hero.jpg");

  background-image: image-set(
    "hero.jpg"    1x,
    "hero@2x.jpg" 2x,
    "hero@3x.jpg" 3x
  );
}
Live demo
The image shown above is the one your screen selected.
Example 02 · Format selection

Modern formats with type()

.banner {
  background-image: image-set(
    "banner.avif" type("image/avif"),
    "banner.webp" type("image/webp"),
    "banner.jpg"  type("image/jpeg")
  );
}
The browser takes the first option whose type it supports — so list the smallest / most modern format first.
Live demo
Option 1 uses fake type image/x-future → skipped. Option 2 (image/png) is chosen.
Example 03 · Combined

Resolution + format together

.card-cover {
  background-image: image-set(
    "cover.avif"    1x type("image/avif"),
    "cover@2x.avif" 2x type("image/avif"),
    "cover.jpg"     1x type("image/jpeg"),
    "cover@2x.jpg"  2x type("image/jpeg")
  );
  background-size: cover;
}

1Filter by type

Options with unsupported type() are discarded first.

2Match resolution

From what remains, the browser picks the density that best fits the screen.

3Order matters

Resolution & type() can appear in either order within one option.

Example 04 · Gradients

Not just URLs — any image

.box {
  background-image: image-set(
    linear-gradient(135deg, #7c6cff, #3dd6c6) 1x,
    linear-gradient(135deg, #d4a64a, #ff7a9c) 2x
  );
}
Any <image> works — including gradients. Handy for tuning visual effects per screen density.
Live demo
Violet → teal = 1x screen · Gold → rose = 2x screen
Compatibility

Fallbacks & the -webkit- prefix

.logo {
  /* 1 — every browser */
  background-image: url("logo.png");

  /* 2 — older Safari / Chromium */
  background-image: -webkit-image-set(
    url("logo.png") 1x,
    url("logo@2x.png") 2x
  );

  /* 3 — standard syntax */
  background-image: image-set(
    "logo.png" 1x,
    "logo@2x.png" 2x
  );
}

↓Cascade fallback

If a browser doesn't understand a declaration it ignores it — the last value it does understand wins.

⚙Prefixed version

-webkit-image-set() is the legacy form; older engines may require url() and support only x units.

✓Or use @supports

@supports (background-image: image-set("a.png" 1x)) to feature-detect.

Comparison

image-set() vs srcset / <picture>

FeatureCSS image-set()HTML srcset / <picture>
WhereStylesheets (backgrounds, decorative)Markup (content images)

Rule of thumb: meaningful images → HTML. Decorative images → CSS image-set().

Takeaways

Best practices

  • Always declare a plain url() fallback first
  • List modern formats first when using type()
  • Keep 1x and 2x — 3x rarely gives visible gains
  • Pair with background-size so every density renders at the same size
  • Use for decorative images only
  • Use HTML srcset for width-based choices
  • Name files clearly: img@2x.avif
  • Check DevTools → Network to confirm the right file loads
